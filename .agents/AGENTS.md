1. 在修改代码后执行对应的编译测试。
2. 在进行功能性、性能、业务逻辑、设计等较大范围修改后，在 `docs/record` 记录.
3. 修复线上bug(非语法等编译错误)后，记录在 `docs/record/bugs` .
4. 查询 API 调用方式、模型协议、供应商 endpoint、请求字段或兼容性时，先使用 `rg` 检索仓库根目录下的 `docs/api-base`；其中已有结论优先于重复联网搜索。
5. 本地 API 基础文档找不到所需内容而必须联网查询时，若结果可能被后续任务复用，应将精简结论、官方来源链接和核对日期补充到 `docs/api-base`，并明确区分官方事实、项目约定和待部署验证项；不要复制整页网页。
