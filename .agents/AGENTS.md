1. 在修改代码后执行对应的编译测试。
2. 在进行功能性、性能、业务逻辑、设计等较大范围修改后，在 `docs/record` 记录.
3. 修复线上bug(非语法等编译错误)后，记录在 `docs/record/bugs` 。bug 文档只收录有工程复盘价值的技术问题（需通过日志、实验、源码分析、文档研究或机制理解才能定位根因的问题，如系统行为异常、SDK/框架问题、依赖交互、并发时序、环境差异、性能资源、网络协议及硬件驱动问题）；拼写、命名、参数遗漏、简单编译错误等直接编码失误不记录。
4. 一份 `docs/record` 的变更记录中涉及的 bug，应各自对应 `docs/record/bugs` 下的一篇详情文档（一篇 bug 文档记录一个问题的现象/根因/修复/验证），并在变更记录末尾以链接列表引用。
5. 查询 API 调用方式、模型协议、供应商 endpoint、请求字段或兼容性时，先使用 `rg` 检索仓库根目录下的 `docs/api-base`；其中已有结论优先于重复联网搜索。
6. 本地 API 基础文档找不到所需内容而必须联网查询时，若结果可能被后续任务复用，应将精简结论、官方来源链接和核对日期补充到 `docs/api-base`，并明确区分官方事实、项目约定和待部署验证项；不要复制整页网页。
