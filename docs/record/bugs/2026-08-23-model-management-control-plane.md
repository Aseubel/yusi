# 模型治理控制面问题记录

日期：2026-08-23

## 已修复原因

- route 的 `riskLevel` 原来只在配置和前端展示，匹配器没有参与风险精确度和通配符排序。
- 预览读取已发布配置，编辑中的模型、Tier 或 route 草稿不会影响候选链。
- 未产生运行态的模型不会出现在健康页，Tier 统计却把这类模型算作健康，造成“未采样”和“正常”的混淆。
- `weight` 统一要求大于 0，使 `ZERO_WEIGHT` 不可达，也无法表达暂时不参加加权随机的成员。
- 管理端没有 reset 运行态接口，模型修复后只能清 Redis 或重启实例；原有 Pub/Sub 事件也没有立即合并到本地窗口。
- route 编辑器可以从主 route 视图修改 Tier 全局策略，fallback Tier 的实际策略不透明。

## 结果

统一 planner、schema v2 校验、结构化控制面快照、草稿预览和 Redis reset 后，候选排序与页面展示使用同一份规则，未知运行态显示为 `UNKNOWN`，reset 不触碰历史调用数据。
