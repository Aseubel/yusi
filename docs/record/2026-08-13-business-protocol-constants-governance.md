# 业务协议常量治理记录

日期：2026-08-13

## 背景

后端多个领域直接使用 `DIARY`、`PLAZA`、`HALF_OPEN`、`WEEKLY`、`IMAGE` 等字符串。它们有些是数据库/API/事件协议，有些只是单个类的实现细节，混在一起会增加改名、排查和复用时的风险。

## 决策

1. 跨类共享、会持久化或对外暴露的值，按领域放入常量目录，并保留原有 code，避免数据库和 API 迁移。
2. 领域枚举负责表达协议语义，并提供 `code()`；需要兼容旧输入的协议提供归一化解析方法。
3. 不建立全局巨型 `Constants.java`。常量按领域归属放置：通用协议在 `common/constant`，DTO/持久化业务值在 `pojo/constant`，LifeGraph、认知、模型、报告和 MCP 值在对应服务包内。
4. 只在一个类内使用的阈值、缓存 key、正则、分页预算、第三方算法名和局部状态机继续封装在所属类，避免为了形式统一破坏内聚性。

## 已治理的协议

- 来源、情绪、生命周期、模型调用状态、聊天角色、开发者权限范围。
- Agent 风格、主动问候频率、密钥模式、匹配动作/反馈、建议状态、中期记忆分类。
- LifeGraph 用户节点标识、关系类型、证据类型、合并状态/判断。
- 模型 provider alias、健康阶段、路由排除原因、状态事件动作。
- 日记附件类型和文字定位类型、报告周期、认知冲突来源/融合动作、MCP 记忆结果类型。
- 连接审计动作和默认原因、用户地点类型、Prompt scope 和默认元数据。

## 兼容性

- 现有数据库值和 API 数字动作码不变，只将生产代码中的裸字符串替换为领域类型的 `code()`。
- 旧模型调用成功状态和来源值仍可被识别；未知值按既有默认行为处理。
- LifeGraph 的自动升级边界和来源证据逻辑未因常量治理放宽：抽取可宽，长期写入仍需用户/重要人物语义和原文证据。

## 验证

- `./mvnw.cmd -DskipTests compile`
- 业务协议常量、LifeGraph promotion、记忆生命周期、模型路由和匹配相关测试。
- 完整后端测试在提交前执行。
