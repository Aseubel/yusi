# Yusi 上线后扩展 Backlog

> **Status:** Deferred — 上线标准达成前不启动
> **Date:** 2026-08-17
> **Scope:** 不属于“完整的、逻辑闭环的、可上线的个人产品”定义的扩展功能；
> 由 [主 roadmap](2026-08-04-yusi-agent-product-roadmap.md) 在 2026-08-17 重构时移出

本文档收纳所有被明确判定为“超出上线定义”的功能方向。它们不是被否决，而是被
排序：主 roadmap 的[上线标准](2026-08-04-yusi-agent-product-roadmap.md#上线标准)
全部具备证据之后，才从本文档按序取回。

## 取回原则

- 上线标准四层（产品闭环、逻辑闭环、质量证据、上线准备）全部达标前，不启动本文档
  任何条目。
- 每个条目取回时仍走既有切片纪律：勘察 -> 设计文档 -> 实施计划 -> 评审 -> 实现 ->
  全量测试，且必须先说明它依赖的上线能力是否稳定。
- 扩展不得破坏已确立的低敏 Trace 边界、删除生效、来源撤销和隐私承诺；任何扩展
  与这些边界冲突时，边界优先。
- 一次只取回一个方向，避免多线扩展稀释线上稳定性。

## 1. 主动陪伴体验深化

移入原因：主动问候现有行为（不活跃判断、冷却、频率、静默时段）已满足上线定义，
深度改造属于体验扩展而非闭环补齐。

- 用聊天、日记、广场和通知记录聚合最近活动，替代只依赖 `mid-memory` 更新时间。
- 将主动触发拆分为回顾、情绪陪伴、重要节点、匹配提醒等明确类型。
- 每次主动消息记录触发原因、使用的认知范围、关联事件和发送结果。
- 支持全局关闭、类型关闭、频率设置、静默时间和单条忽略的完整控制面板。
- 对主动消息做去重、冷却、失败重试和幂等控制的增强。
- 优先生成可执行的入口，例如“回顾这段经历”“继续昨天的话题”，减少泛化问候。
- 在连接互动阶段补充经过评测的定时触达和反馈时机，不把触达当作连接质量的唯一指标。
- 主动性评测集深化：触发是否合理、活动判断是否准确、内容是否重复、是否造成打扰。

取回前置条件：上线后的真实主动问候运行数据可观测（依赖 Phase 5 的指标与告警）。

## 2. 持久化 Agentic Runtime

移入原因：Runtime 的迁移对象是“需要暂停、确认和恢复的流程”，而当前唯一写工具
`updateUserPersona` 已被声明式幂等账本覆盖，确认流程无真实消费者。

- 只将需要暂停、确认和恢复的流程迁移到持久化 Agentic Runtime，不重写普通同步服务。
- 候选场景：用户请求删除一组长期记忆、Agent 整理较长人生阶段记录、用户确认后才把
  一次情景结果用于匹配。

取回前置条件：写操作用户确认边界（主 roadmap Phase 3 剩余项）已实现且出现真实
非幂等写工具消费方。

## 3. Agent 能力扩展

移入原因：平台能力扩张必须由真实任务驱动，不属于上线闭环。

- 为复杂记忆整理或匹配准备流程试点 Supervisor + 专业能力。
- 评估语音对话，优先考虑日记和低门槛表达场景。
- 评估外部知识接入和个人数据连接器。
- 评估多应用 API Key、配额和 MCP 工具生态。
- 在评测体系稳定、有足够高质量数据后，再评估微调或专用模型。

取回前置条件：对应真实需求出现，且相关评测集（主 roadmap Phase 4）已能度量其影响。

## 4. 评测与训练深化

移入原因：训练与数据工厂不是上线必需；先保证评测可复现。

- 将用户反馈转成脱敏、可标注的数据，不直接把所有反馈写回画像或训练数据。
- 建设 Prompt / 模型 / 检索策略的自动化版本对比面板。
- 微调或专用模型训练工厂。

## 5. 平台化与商业化方向（长期非目标）

以下方向与“隐私优先的个人产品”定位冲突，除非产品定位发生明确变化，否则不进入
任何阶段计划：

- 飞书、Slack、钉钉等企业渠道适配。
- 企业多租户、组织权限、计费和配额平台。
- 完整的四专家 Agent Swarm。
- MCP 工具市场和第三方工具生态。
- 新用户冷启动、激活漏斗、强制 onboarding、连续打卡或奖励式数据收集。
