# Yusi 管理端工作台重构设计

日期：2026-08-24

状态：已确认，已实现；浏览器验收受现有管理员会话限制

## 1. 背景与现状

当前管理端包含总览、用户、情景审核、Prompt、模型、建议、通知和安全审计等入口。它们分别维护自己的标题、筛选器、表格或卡片、分页和详情行为，导致以下问题：

- 管理端页面缺少统一的信息层级和操作节奏，像若干独立 demo 的拼接。
- 总览无法直接回答模型调用次数、Token 消耗、成功率、Fallback 和延迟趋势。
- 模型调用活动虽已支持后端分页查询，但前端只有上一页/下一页，没有范围、页码、页大小和可恢复查询上下文。
- Prompt 编辑表单直接插在列表前，页面主任务被表单打断。
- 模型注册编辑使用 Sheet，Radix Select 的 Portal 内容可能被 Dialog/Sheet 误判为外部点击，选择 Provider 或 Protocol 时编辑面板意外关闭。
- 用户、审核、建议和审计页面的详情、分页、空状态、错误状态和危险操作保护不一致。
- 现有共享 Card 默认带大圆角、玻璃背景和 hover 位移，管理端的信息扫描稳定性不足。

后端已经持久化低敏 `model_call_trace`，包括调用状态、路由、模型、Token、成本、延迟和错误分类；新增设计应基于这些真实数据，不使用前端假数据，也不得扩大敏感内容暴露边界。

## 2. 目标与边界

### 2.1 目标

1. 把 `/admin/*` 统一为可支持运营、审核和技术排障的管理工作台；同一个使用者可以在三种工作模式之间切换，不为不同角色复制三套导航。
2. 让模型治理总览能直接回答调用量、输入/输出/总 Token、成功率、Fallback、延迟、成本和近期异常。
3. 让调用活动成为真正可查询的低敏操作台，具备筛选、分页、页码跳转、页大小、详情和 URL 状态恢复。
4. 让 Prompt、模型注册、审核、建议和通知等编辑或处理流程在右侧 Panel 内完成，不把大表单固定塞在列表上方或切换成另一整页。
5. 建立管理端共享组件和行为约定，统一加载、空、错、刷新、保存、成功反馈、危险确认和移动端布局。
6. 修复 Sheet 与 Select 的 outside-click 边界，同时保留遮罩、关闭按钮和 Escape 的正常退出路径。
7. 保留现有鉴权、审计和低敏边界；不展示或持久化 Prompt 正文、回答、思考内容、图片 URL、API key 或完整上游响应体。

### 2.2 不做

- 不引入新的请求状态管理框架；继续使用现有 Axios、React hooks、React Router 和 i18next。
- 不凭空补充没有后端来源的趋势或统计数据；没有数据时展示诚实的空状态。
- 不把管理端重构扩展为新的业务领域，不修改用户端核心体验。
- 不新增过程性文档；本任务只维护本 spec、一个 implementation plan 和一个 implementation record。

## 3. 整体信息架构

管理端导航按工作类型分组，保持一个统一工作台：

```text
工作台
  总览

运营
  用户
  建议
  通知

内容审核
  情景审核

AI 平台
  Prompt
  模型治理

安全
  审计日志
```

桌面端使用可折叠侧边栏，移动端使用同一导航的 Sheet。导航项显示图标和文本标签，当前路由有稳定的 active indicator；不会在不同页面混用多套同层级导航。

所有页面共用以下骨架：

1. `AdminPageHeader`：标题、简短说明、刷新和单一主操作。
2. `AdminToolbar`：搜索、筛选、时间范围、视图相关辅助操作。
3. 主数据区：桌面端表格或队列，移动端转为可扫描列表。
4. `AdminPagination`：总数、当前范围、页大小、页码、前后页和加载禁用状态。
5. `AdminDetailSheet`：只读详情、编辑、审核或回复操作的统一容器。
6. 统一的 Loading、Empty、Error/Retry、Saving、Success 和 Destructive 状态。

列表页的筛选、排序（如已有接口支持）和分页通过 `useSearchParams` 同步 URL。刷新或返回页面时恢复查询上下文；筛选变化将页码重置为 0，加载期间禁止重复提交和越界翻页。

视觉方向为“运维控制台 + 现代工作台”：列表与审核页高密度、边界清晰、稳定行高；总览页使用更强的图表层级和留白。管理端 surfaces 使用不超过 8px 的圆角、轻量边框和稳定阴影，不使用大面积玻璃效果、卡片 hover 位移或装饰性渐变。

## 4. 页面设计

### 4.1 管理首页

管理首页只展示真实的系统和业务概览：用户总量、今日/7 日/30 日活跃用户、日记、房间、待审核情景和待回复建议。指标下方提供待处理队列，直接链接到情景审核和建议页面；保留超级管理员专属的 Embedding 全量同步危险操作，并使用明确确认。

模型调用趋势不在这里复制一套不完整的统计，而在模型治理总览集中展示。首页的每个指标只有在来源真实可用时才显示趋势或辅助信息。

### 4.2 用户管理

- 统一为搜索工具栏、用户表格和标准分页。
- 表格显示用户 ID（可复制/查看完整值）、用户名、权限等级、匹配状态和操作。
- 权限修改打开 Panel，展示当前等级、可选等级、权限限制和保存结果；不能修改自己、同级或更高权限用户。
- 超级管理员的注销操作使用危险确认，明确不可恢复，并在成功后刷新当前页数据。
- 移动端使用字段分组列表，不隐藏权限和危险操作。

### 4.3 情景审核

- 默认过滤待审核状态，并提供状态切换和刷新。
- 用表格/队列替代大卡片网格，显示标题、来源、提交时间、状态和打开详情操作。
- 点击记录打开 Panel，完整显示描述、来源、创建/更新时间和驳回原因。
- 待审核记录在 Panel 底部提供批准和驳回；驳回必须填写原因，操作中锁定按钮并在成功后更新列表。
- 分页显示总记录、当前范围、页码和页大小。

### 4.4 建议管理

- 列表显示状态、内容摘要、联系方式、提交时间和更新时间；状态筛选使用统一工具栏。
- 点击记录打开 Panel，不再通过整页替换进入详情。
- Panel 内显示原始建议、已有回复、回复人/时间；待回复建议提供回复编辑器和发送状态。
- 状态更新与处理时间设置在同一 Panel，成功后保留当前筛选并刷新记录。

### 4.5 通知管理

- 主页面以发布历史为主，显示标题、受众、收件人数、状态和发布时间。
- “发布通知”打开编辑 Panel；标题、正文、受众和字数限制在 Panel 内完成。
- Panel 内保留实时预览，发布前二次确认；发布成功清空草稿并回到历史第一页。
- 历史记录使用标准分页和加载骨架，不把发布表单长期占据主列表上方。

### 4.6 Prompt 管理

- 主区域始终是 Prompt 列表，支持名称搜索、scope、locale、active 状态、页大小和完整页码。
- 列表显示名称/描述、scope、locale、版本、状态、默认标记、优先级和更新时间。
- 新建和编辑都打开右侧 Panel；编辑表单包含基本信息、模板正文、开关和固定底部操作栏。
- Panel 关闭前检测未保存变更，提供继续编辑或放弃变更的明确路径。
- 点击列表项可打开只读详情 Panel，查看模板元数据和正文；编辑按钮进入编辑状态。
- 模板正文仅在管理员详情/编辑 Panel 中显示，不进入列表统计、日志或新增调用图表。

### 4.7 模型治理

保留四个工作区：总览、模型注册、场景路由、调用活动。

- 总览显示真实调用统计、Token、成本、延迟、Fallback、运行健康和近期异常。
- 模型注册列表显示 Provider、真实模型 ID、能力、运行状态、权重/优先级、价格状态和所属 Tier；新增/编辑使用右侧 Panel。
- Tier 成员与策略保留在模型工作区，但通过清晰分区表达模型字段和 Tier 字段的责任边界。
- 场景路由保留当前草稿预览、主 Tier、Fallback 顺序、预算和风险级别；预览结果与当前草稿一致。
- 调用活动使用新的统计摘要、筛选、分页和详情 Panel。

`SheetContent` 和管理端 `Select` 需要共同支持：Select 的 Portal 内容不触发 Sheet 的外部关闭；真实点击遮罩、关闭按钮或 Escape 仍关闭 Sheet。关闭带未保存变更的编辑 Panel 必须先确认。

### 4.8 安全审计

- 工具栏统一提供动作、结果、资源类型和用户 ID 过滤。
- 表格显示时间、动作、操作者、主体、资源、结果和原因摘要。
- 详情 Panel 显示低敏 details 的结构化键值，长值可换行，不在表格中堆叠大量 Badge。
- 分页和 URL 筛选状态可恢复；刷新只刷新当前查询。

## 5. 模型统计数据契约

现有 `GET /api/model/metrics` 的汇总语义扩展为明确的调用统计。`routeCount` 更名或兼容投影为 `callCount`，表示过滤条件下的调用轨迹数，而不是路由规则数。汇总字段包括：

```text
callCount
fallbackCount
fallbackRate
successRate
averageLatencyMs
p95LatencyMs
rateLimitedCount
errorCount
inputTokens
outputTokens
totalTokens
knownCost
unknownCostCount
```

新增时间序列查询（具体路径在实现计划中固定为单一版本）返回：

```text
bucket: HOUR | DAY
from
to
items: [
  {
    bucketStart,
    callCount,
    successCount,
    errorCount,
    fallbackCount,
    inputTokens,
    outputTokens,
    averageLatencyMs
  }
]
```

接口接受现有的时间、场景、用户、Tier、Provider、模型、Fallback 和状态过滤。数据库层执行时间分桶和 `COUNT/SUM/AVG` 聚合，不把指定时间范围的全部 trace 拉入 JVM；已有的低敏字段投影继续生效。P95 若数据库方言不提供稳定聚合函数，继续采用明确的样本不足状态或受限查询，不伪造精度。

总览图表：

1. 调用量趋势：成功、失败、Fallback。
2. Token 趋势：输入和输出。
3. 延迟趋势：平均延迟；P95 作为可用时的辅助指标。
4. 运行状态分布：健康、探测中、不可用、未知。
5. 最近异常列表：失败分类、模型、场景、时间，可带着筛选条件跳转调用活动。

图表必须有图例、精确值交互、键盘可达的文本摘要和等价汇总表；无数据时显示指导性空状态，不显示假坐标轴。

## 6. 共享组件与数据层

新增或重构管理端专用组件，建议放在 `frontend/src/components/admin/`：

- `AdminPageHeader`
- `AdminToolbar`
- `AdminSurface`
- `AdminTable`
- `AdminPagination`
- `AdminDetailSheet`
- `AdminStatusBadge`
- `AdminEmptyState`
- `AdminChartPanel`

新增少量纯逻辑工具，建议放在 `frontend/src/lib/admin/`：

- Page payload 归一化（`content`, `totalElements`, `totalPages`, `number`, `size`）。
- 页码窗口生成和范围文案。
- URL 查询参数序列化/反序列化。
- 模型统计数字和时间格式化。

不修改用户端的视觉语义；管理端页面逐步改用 `AdminSurface`，避免全局 `Card` 的玻璃背景和 hover 位移继续影响操作台。现有 `adminApi`、`promptApi` 和 `modelApi` 会补齐类型化的建议/通知/统计查询方法，减少页面直接拼接 URL 的情况。

## 7. 错误处理与安全边界

- 所有请求错误在对应区域显示原因和重试入口；Toast 只作为补充，不作为唯一错误提示。
- 异步按钮显示 loading 并禁用重复提交；保存成功后关闭 Panel 或更新局部数据，避免无提示地刷新整页。
- 关闭含未保存变更的 Panel 必须确认；删除、注销、全量同步和模型 reset 继续使用危险确认。
- 管理页面遵守管理员鉴权；前端隐藏操作不是权限控制，后端接口继续作为最终授权边界。
- 新增统计 DTO、日志和图表只允许低敏汇总：不得包含 Prompt 正文、回答、思考内容、图片 URL、API key 或完整上游响应体。
- 路由和调用详情只展示现有低敏 ID、分类、版本和摘要；不得通过图表 tooltip 绕过 DTO 边界。

## 8. 验证策略

实现阶段按测试先行推进：

1. 先为分页窗口、Page 归一化、URL 查询状态和统计格式化写纯逻辑测试，先确认失败再实现。
2. 为后端统计聚合、时间范围、过滤条件和管理员边界写 focused tests；确认查询不返回敏感字段。
3. 为 Prompt Panel 未保存确认、Select 不误关闭 Sheet、分页跳转和统计数据投影补充可重复的组件/集成验证；若现有测试环境不含 DOM 测试工具，使用当前可用的轻量测试方式并通过浏览器手工回归关键交互。
4. 运行前端 `pnpm test`、`pnpm lint`、`pnpm build`；运行相关 Maven 测试和后端编译；执行 `git diff --check`。
5. 启动前端开发服务，在桌面和移动视口检查总览图表、表格横向适配、Prompt/模型 Panel、Select 选择、分页和危险操作；验证 reduced-motion 下不依赖动画表达状态。

验收不以“页面能打开”为标准，而以真实接口数据、可完成的工作流、可恢复查询上下文和明确的错误/保存反馈为标准。
