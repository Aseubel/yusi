# LifeGraph 独立来源追踪与日记重建设计

## 背景

当前 `DiaryChangedEvent` 会创建 LifeGraph 任务，由 GraphRAG 抽取实体、关系和提及。

LifeGraph 的实体提及已经通过 `life_graph_mention.diary_id` 保存来源，但关系表只有一个 `evidence_diary_id`。同一关系被多篇日记提及时，后一次抽取会覆盖前一次来源；关系删除也只能按单个字段直接删除，无法知道还有哪些日记贡献了这条关系。日记修改后再次抽取时，旧的提及、关系权重和证据没有形成可独立撤销的来源单元，重复处理会污染聚合结果。

本设计只记录 LifeGraph 的长期来源追踪方案。前端图库合并、记忆中心日记标题跳转和中期记忆替换属于同一需求中的实现项，不纳入本长期设计文档。

## 目标

- 每次自动抽取的实体提及和关系证据都能独立定位到来源日记。
- 日记修改或删除时，只撤销该日记产生的 LifeGraph 贡献。
- 其他日记仍然贡献的实体、关系和关系权重不受影响。
- 同一篇日记重复处理是幂等的，不因重试或重复事件增加实体计数、关系权重或证据行。
- 保留人工创建的关系，并兼容已有只有 `evidence_diary_id` 的历史关系。
- 日记内容为空或解密失败时，也要撤销该日记的旧来源，不能让旧结果继续出现在 Timeline 或关系图谱中。

## 非目标

- 不把原始日记内容或敏感片段暴露给前端来源接口。
- 不改变 Timeline 的业务定义；Timeline 仍读取可见且未过期的 `Event` 实体。
- 不把每次 LLM 原始响应作为用户可见数据长期保存。
- 不在本设计中重构统一认知编排的所有输出模型。

## 数据模型

### 实体提及

继续使用 `life_graph_mention` 作为实体来源证据：

- `user_id + entity_id + diary_id` 标识一篇日记对一个实体的来源贡献。
- 重新处理日记前删除该日记的提及，再写入新提及。
- `mention_count` 表示实体被来源日记贡献的次数；同一篇日记重复处理不得重复增加。
- 删除实体前先撤销该日记贡献；只有没有剩余来源贡献时才删除自动生成实体及其别名。

实现时按实体和来源日记去重，避免一次 LLM 响应中重复实体导致计数不一致。提及明细仍可保存多个证据片段，但撤销计数以该来源日记对实体的唯一贡献为准。

每个抽取实体至少写入一条 `life_graph_mention` 来源行；即使模型没有返回显式 `mentions` 数组，也用实体本身建立来源关联。这样实体计数和来源撤销不会因模型输出字段缺失而失配。

### 关系来源证据

新增 `life_graph_relation_evidence` 表，关系聚合行和来源证据行分离：

| 字段 | 作用 |
| --- | --- |
| `id` | 证据主键 |
| `user_id` | 所属用户，所有查询和删除都必须带上 |
| `relation_id` | 关联 `life_graph_relation.id` |
| `source_type` | 当前自动抽取使用 `DIARY`；历史无法还原的贡献使用 `LEGACY` |
| `source_id` | `DIARY` 时为日记业务 ID；`LEGACY` 时为稳定的迁移标识 |
| `occurrence_count` | 该来源对关系权重的贡献次数 |
| `evidence_snippet` | 脱敏后的短证据，可为空 |
| `confidence` | 该来源证据置信度 |
| `created_at` / `updated_at` | 审计时间 |

唯一键为 `relation_id + source_type + source_id`。同一篇日记重新抽取同一关系时更新现有证据，不新增权重；日记修改前删除其来源证据，再由新结果写回。

`life_graph_relation.weight` 继续作为聚合读取字段，其值由来源证据的 `occurrence_count` 汇总。`evidence_diary_id` 暂时保留用于兼容旧读取方，但不再作为来源真相；写入时只维护为最新已知日记来源。

关系额外保存 `manual_weight` 作为人工基线：人工关系的当前权重为 `manual_weight +` 剩余自动日记证据权重；自动关系的 `manual_weight` 为 0。人工修改关系权重时同步更新基线，日记撤销只重算自动证据部分。

### 关系来源类型

关系增加 `origin` 字段：

- `AUTO`：由认知抽取产生，有来源证据时随来源撤销。
- `MANUAL`：用户或管理接口创建，没有来源证据时保留。

迁移时根据旧 `evidence_diary_id` 将可识别关系标记为 `AUTO`，其余关系默认 `MANUAL`。历史 `weight` 中无法还原来源的部分写入一条 `LEGACY` 证据，避免修改已知日记时误删未知贡献；`MANUAL` 关系的迁移权重同时回填为 `manual_weight`，`AUTO` 关系回填为 0。

## 来源撤销与重建流程

### 日记修改或重试

LifeGraph 任务处理按以下顺序执行：

1. 以 `user_id + diary_id` 合并同一日记的待处理任务；已有处理中任务完成后再处理一个后续任务，避免同一来源并发重建并保留最新修改。
2. 删除该日记的关系证据，并对受影响关系重新汇总权重；没有剩余证据的 `AUTO` 关系删除，`MANUAL` 关系保留。
3. 删除该日记的实体提及，并按唯一实体来源贡献减少 `mention_count`；没有剩余提及时删除自动实体及其别名。
4. 读取当前版本日记；内容为空或无法解密时只完成来源撤销，不执行 GraphRAG 抽取，否则执行一次 GraphRAG 抽取。
5. 写入实体、提及、关系和关系来源证据；同一来源的写入必须使用唯一键或等价的幂等逻辑。
6. 只有新版本处理成功后才将任务标记为完成；失败时保留可重试状态，不能留下“旧结果已删除但新结果未生成且任务已完成”的状态。

删除日记只执行第 2、3 步，不生成新结果。

## 历史数据迁移

新增数据库迁移：

1. 增加 `life_graph_relation.origin` 和 `manual_weight`，设置默认值。
2. 创建 `life_graph_relation_evidence` 及用户、关系、来源索引和唯一键。
3. 对旧关系：
   - `evidence_diary_id` 非空时写入一条 `DIARY` 证据；
   - `weight` 超出已知证据的部分写入 `LEGACY` 证据；
   - `evidence_diary_id` 为空且 `weight > 0` 时写入 `LEGACY` 证据；
   - 按可识别来源标记 `origin=AUTO`，其余标记 `origin=MANUAL`。
4. 不删除原 `evidence_diary_id`，以支持回滚和旧版本读取。

`init.sql` 同步反映最终表结构，但不承担线上历史数据迁移职责。

## 一致性与失败处理

- 来源撤销、聚合计数更新、关系证据写入在同一数据库事务内完成。
- LLM 调用不在持有数据库锁的短事务中执行；任务先领取，再按来源版本校验，避免长事务占用锁。
- 若抽取失败，旧来源已经撤销时任务必须重试；不允许通过“保留旧结果”掩盖失败，否则用户修改后的来源内容会继续参与检索。
- 若处理期间日记产生新修改，旧任务不得覆盖新版本；任务应重新读取最新日记或重新入队。
- 所有仓储删除方法都包含 `user_id`，禁止仅凭自增 ID 或 `diary_id` 跨用户操作。

## 验证

- 同一日记重复处理两次：实体计数、关系权重、提及数量和关系证据数量不增加。
- 关系由两篇日记共同产生：删除其中一篇后关系仍存在，权重只减少该来源贡献，剩余来源可查询。
- 关系只有一篇日记来源：删除该日记后自动关系和其证据删除。
- 人工关系没有来源证据：删除日记不影响人工关系。
- 人工关系同时有日记证据：删除日记只移除自动证据，人工基线仍保留。
- 历史关系含未知权重：删除已知日记后 `LEGACY` 贡献仍保留。
- 抽取失败：任务可重试，且不会被错误标记完成。
- 多用户同 ID 场景：来源撤销只影响当前用户。
